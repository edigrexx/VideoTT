# Проверки MVP

Последнее обновление: 2026-09-12.

## Сборка сценария из отдельных фрагментов

- Реальное задание `3e916b69-17f6-43de-9bf3-b93c0a666c31` остановилось из-за вступления длиннее 10 слов после одного исправления. Предыдущая схема требовала дублировать вступление/концовку в сценах, а затем сцены в общем тексте; проверка сообщала только первое нарушение длины.
- Новый ответ LLM `ScriptDraft` содержит отдельные hook/payoff и основные тексты сцен, без общего narration и номеров сцен. Приложение собирает существующий `Script`, сохраняя порядок текста, факты, поисковые запросы и формат базы/API. Текст не обрезается и не дописывается программой: она только соединяет предоставленные фрагменты.
- Проверки длины hook и narration выполняются независимо и сообщают обе ошибки сразу. Замечания к исправлению учитывают отдельно длину вступления, общую длину и бюджеты основных текстов сцен. Допускаются максимум два исправления любого невалидного полного сценария, без повторного исследования.
- Тестами проверены сборка прежнего сценария без потери текста, отсутствие лишних полей в схеме API, неизменность исходного черновика, сохранение ограничения вступления, одновременные ошибки длины и ограничение числа запросов. Отказы, неполные ответы, HTTP-ошибки и проверки доказательств по-прежнему не обходятся.
- Локально: **107 passed, 3 PostgreSQL tests skipped**; Ruff и проверка diff прошли. Проверены оба адаптера, OpenRouter и OpenAI; полный Compose/PostgreSQL прогон выполняется в CI.
- Реальный готовый ролик пока не подтверждён; требуется повтор после обновления на сервере.

## Исправление длины сценария

- Реальное задание `7c2106e3-08b2-4b42-87c7-2df9f64b7c19` прошло исследование, но сценарий дважды не уложился в 135–215 слов. Старое сообщение не показывало фактическую длину, поэтому неизвестно, был тот сценарий коротким или длинным.
- Счётчик слов теперь общий для проверки и обратной связи модели. Ошибка содержит фактический объём без текста сценария. Для русского сценария инструкция задаёт девять сцен примерно по 17 слов; при правке передаются вычисленные объёмы сцен, общий объём и число слов, которое нужно добавить или убрать до ориентира.
- Только повторная ошибка числа слов допускает второе исправление сценария (максимум три ответа). Прочие ошибки структуры по-прежнему допускают одно исправление, HTTP/refusal/incomplete не повторяются. Исследование не перезапускается; учитывается стоимость каждого полученного ответа.
- Проверяются короткие и длинные ответы, успешное первое/второе исправление, остановка после двух неудачных исправлений, точность обратной связи, отсутствие текста в ошибке и строгие границы 134/135/215/216 слов. Реальная длительность озвучки всё ещё проверяется отдельно.
- Локально: **103 passed, 3 PostgreSQL tests skipped**; Ruff и проверка diff прошли. Полный Compose/PostgreSQL прогон выполняется в CI.
- Реальный готовый ролик пока не подтверждён; исправление проверяется после обновления на сервере.

## Исправление пар «источник — цитата»

- Реальное задание `e21404d4-4a4b-4efa-9831-28bdb5c6aef0` остановилось с `FACT_EVIDENCE`: число ссылок факта не совпало с числом цитат. В ответе модели два параллельных списка заменены обязательными парами `source_url` / `quote`; преобразование в прежний формат хранения выполняет приложение.
- При невалидных цитатах или повторных ID допускается ровно одно исправление по тем же скачанным источникам. Поиск и скачивание не повторяются. Неудачный результат сохраняется и блокируется проверкой до SCRIPTING. Поля ошибок содержат индексы и причину без цитат и URL.
- Проверяются пары с несколькими источниками, запрет отсутствующей цитаты, успешное и неуспешное исправление выдуманных цитат/URL/повторных ID, предел двух извлечений, отсутствие нового поиска, стоимость обоих ответов и сохранение отклонённого исследования без генерации сценария.
- Локально: **88 passed, 3 PostgreSQL tests skipped**; Ruff и проверка diff прошли. Полный PostgreSQL/Compose прогон выполняется в CI.
- Реальный первый готовый ролик пока не подтверждён; после обновления необходим повтор на сервере с ключами пользователя.

## Диагностика и исправление невалидного сценария

- На сервере пользователя повторное задание `4169ebc2-685c-4f02-af1c-c5c424d7bd5d` прошло RESEARCHING и дошло до SCRIPTING; HTTP 400 в этой попытке не повторился. Затем получен `LLM_SCHEMA`. Старое сообщение не различало нарушения сценария и формата оценки, поэтому точное нарушенное правило неизвестно.
- Сообщения валидации теперь содержат тип ответа, путь поля и причину без входных текстов и произвольных имён полей из ответа модели. Для Gemini полные ограничения передаются текстом в инструкции, сохраняя упрощённую схему API.
- Только невалидный Script получает одну попытку исправления по замечаниям на основе исходного исследования. Поиск повторно не вызывается, оба ответа учитываются в расходах. Повторная ошибка останавливает задание; проверки языка и достоверности сохранены.
- Тестами проверены успешное исправление, остановка после двух невалидных ответов, отсутствие исправлений при HTTP/refusal/incomplete, учёт обеих стоимостей и безопасные сообщения для длины текста, порядка сцен, длительности, хэштегов, лишних полей и невалидного JSON.
- Локально: **78 passed, 3 PostgreSQL tests skipped**; полный Compose/PostgreSQL прогон выполняется в CI. Реальный результат нового сценария ещё требует обновления и повторного запуска на сервере.

## Диагностика HTTP 400 на сервере пользователя

- Реальный первый запуск остановился во время RESEARCHING с HTTP 400. Предыдущий код скрывал тело ответа, поэтому конкретный отклонённый параметр пока не установлен.
- Добавлены этап запроса (`source_search`, `ResearchResult`, `Script`, `Evaluation`) и выбранные сообщения валидации из OpenRouter / вложенной ошибки провайдера. Ключи, Bearer-токены и URL удаляются до ограничения длины сообщения; произвольные raw-тела не выводятся.
- Для Gemini отправляется упрощённая JSON-схема: ссылки на вложенные типы раскрыты, ограничения длины, количества элементов и диапазонов проверяются в приложении. Структура объектов, типы, обязательные поля и запрет дополнительных полей сохранены. Остальные модели получают исходную схему.
- Проверены вложенная ошибка, удаление чувствительных значений, неизвестные форматы и отсутствие автоматического повтора. Отдельные тесты подтверждают, что упрощение схемы API не позволяет принять пустой список фактов, слишком длинный текст или несогласованный сценарий.
- Локальный результат: **68 passed, 3 PostgreSQL tests skipped**. Полный Compose/PostgreSQL прогон запускается в CI.
- На скриншотах пользователя есть три успешных upstream-запроса Gemini 2.5 Flash и затем четыре отказа маршрутов следующего запроса. Подробный текст причины не показан. Упрощение устраняет потенциальную несовместимость, описанную Google, но **исправление конкретного реального HTTP 400 ещё требует повторного запуска на сервере**.
