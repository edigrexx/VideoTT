# Первый запуск с OpenRouter в Dokploy

Программа готова к тестированию. Поддержка OpenRouter проверена автоматическими тестами с подменой HTTP-ответов. Реальное качество исследования, сценария и стоков проверяется после добавления ваших ключей. Не включайте ежедневное расписание до просмотра первого настоящего ролика.

## 1. Подготовьте ключи и Environment

В [OpenRouter → Settings → Keys](https://openrouter.ai/settings/keys) создайте ключ **VideoTT**. На первые тесты задайте ему лимит **$1**. Уже внесённые $10 используются с общего баланса; дополнительный OpenAI API key не нужен. Лимит ключа можно затем увеличить.

Получите второй ключ на [Pexels API](https://www.pexels.com/api/). Он нужен для поиска и скачивания видеоклипов.

На компьютере откройте `.env` в папке TTVideo: пять внутренних секретов уже созданы. Не меняйте их и не публикуйте файл. Если работаете с новой копией репозитория без `.env`, сначала выполните `python3 scripts/setup_env.py`.

В Dokploy → проект VideoTT → сервис Docker Compose → **Environment** перенесите весь `.env`. Затем задайте следующие значения (вместо пояснений после `=` вставьте настоящие ключи):

```dotenv
LLM_PROVIDER=openrouter
LLM_MODEL=google/gemini-2.5-flash
LLM_API_KEY=ваш_ключ_OpenRouter
PEXELS_API_KEY=ваш_ключ_Pexels
STOCK_PROVIDER=pexels
TTS_PROVIDER=edge
CONTENT_LANGUAGE=ru-RU
TTS_VOICE=ru-RU-SvetlanaNeural
ALLOW_TEST_MODE=false
OPENROUTER_MAX_TOKENS=8192
OPENROUTER_REASONING_TOKENS=1024
OPENROUTER_MAX_SEARCHES=2
```

Ключи сохраняются только в Environment или локальном `.env`. Не вставляйте их в команды терминала, GitHub и сообщения.

Сценарий, озвучка, субтитры и описание создаются на русском. Голос по умолчанию женский; для мужского задайте `TTS_VOICE=ru-RU-DmitryNeural`. При обновлении замените старый английский голос и добавьте `CONTENT_LANGUAGE=ru-RU`, затем повторите Deploy. Поиск Pexels остаётся на английском, а цитаты доказательств сохраняют исходный язык. Уже созданные ролики не переводятся; создайте новое задание.

## 2. Разверните приложение

Если сервиса ещё нет: создайте в Dokploy **Project → Docker Compose**, подключите репозиторий `https://github.com/edigrexx/VideoTT.git`, ветку `main`, Compose path `./docker-compose.yml`.

Сохраните Environment и нажмите **Deploy**. Дождитесь здоровья `postgres`, `worker`, `runner`, `n8n`. Сервис `migrate` должен завершиться с кодом **0** — это нормально. При обновлении используйте свежий коммит `main` и повторный Deploy. База и видео сохраняются в volumes.

## 3. Проверьте ключи

В Dokploy откройте терминал контейнера **worker**:

```bash
python scripts/check_providers.py
```

Ожидается `OK` для OpenRouter key, OpenRouter model и Pexels. Проверка не запускает генерацию и платный веб-поиск: она читает сведения ключа, каталог моделей и делает один запрос поиска Pexels. Она не подтверждает полный баланс аккаунта, работоспособность платного поиска, озвучки или качество видео.

Если терминал Dokploy открывает оболочку сервера вместо контейнера, перейдите в каталог Compose и выполните `docker compose exec worker python scripts/check_providers.py`.

## 4. Создайте один ролик

В том же терминале **worker**:

```bash
python scripts/client.py create --wait
```

По умолчанию тема — почему на клавишах F и J есть выступы. Команда покажет `video_id`, `job_id`, затем этапы работы. Дождитесь **READY**. Каждый повтор команды `create` создаёт новое платное задание; для проверки существующего используйте:

```bash
python scripts/client.py get --id VIDEO_UUID
```

Замените `VIDEO_UUID` на полученный `video_id`. При `NEEDS_REVIEW` проверьте исследование/сценарий и ошибку: ролик остановлен из-за недостаточных источников, несогласованного текста или проверки фактов. Это не готовое видео. При `FAILED` исправьте причину; повторный запуск исследования может стоить денег.

Для другой темы:

```bash
python scripts/client.py create --topic "Why are airplane windows rounded?" --wait
```

## 5. Скачайте и посмотрите

Для локального сервера откройте SSH-туннель **на своём компьютере**, подставив свой SSH-логин и адрес сервера:

```bash
ssh -N -L 8000:127.0.0.1:8000 your-user@SERVER_IP
```

Пока терминал открыт, перейдите в браузере на `http://localhost:8000/docs`. Логин **videott**, пароль — значение **WORKER_API_KEY** из Environment. Здесь можно и создавать задания, и проверять их статус.

Готовые файлы доступны в том же браузере:

- `http://localhost:8000/api/v1/videos/VIDEO_UUID/download` — MP4.
- `http://localhost:8000/api/v1/videos/VIDEO_UUID/caption` — описание и хэштеги.
- `http://localhost:8000/api/v1/videos/VIDEO_UUID/metadata` — источники и расход OpenRouter.
- `http://localhost:8000/api/v1/videos/VIDEO_UUID/manifest` — авторы и лицензии клипов.

Если настроили HTTPS-домен worker в Dokploy, используйте его вместо `http://localhost:8000`; туннель не нужен. Просмотрите озвучку, субтитры и соответствие клипов рассказу. Публикуете MP4 вручную. Расписание n8n подключайте после успешной проверки — [инструкция](../README.md#настроить-n8n).

## Расход и ошибки

В `metadata.json` поле `llm_usage.reported_cost_usd` содержит сумму стоимости **полученных ответов текущей попытки**, сообщённую OpenRouter. В `requests` видны этапы, токены и request IDs. `complete=false` означает, что провайдер не вернул стоимость хотя бы одного ответа: такая сумма неполная.

Это не общий баланс и не жёсткий долларовый лимит. Предыдущие попытки, запросы с потерянным ответом и комиссия пополнения в эту сумму не входят. Точный расход аккаунта смотрите в [OpenRouter Activity](https://openrouter.ai/activity). Внутренние журналы каждого задания сохраняются в `/data/media/jobs/VIDEO_UUID/attempt-*/llm_usage.jsonl`, включая остановленные задания. В логах runner доступны события `LLM_USAGE`.

Поиск использует Exa через OpenRouter: отдельный ключ Exa не нужен. На попытку разрешено до двух поисков, до восьми результатов суммарно и 2000 символов выдержки на результат. Последующие извлечение фактов, сценарий и проверка фактов идут без инструмента поиска. Полные публичные источники приложение дополнительно загружает и проверяет самостоятельно.

| Код | Что делать |
|---|---|
| `OPENROUTER_AUTH` | Проверить LLM_API_KEY и повторить Deploy |
| `OPENROUTER_CREDITS` | Проверить баланс аккаунта и лимит ключа |
| `OPENROUTER_ACCESS` | Проверить доступ аккаунта/провайдера к модели |
| `OPENROUTER_RATE_LIMIT` | Подождать и повторить вручную |
| `OPENROUTER_TIMEOUT` | Сначала посмотреть Activity: запрос мог быть оплачен |
| `OPENROUTER_HTTP` / `OPENROUTER_UPSTREAM` | Проверить модель, статус OpenRouter и Activity |
| `LLM_INCOMPLETE` | Проверить лимит ответа; при необходимости увеличить MAX_TOKENS, учитывая цену |
| `LLM_SCHEMA` | Модель вернула несовместимый JSON/сценарий; проверить результат и повторить вручную |
| `LLM_LANGUAGE` | Модель вернула нерусский сценарий; повторить генерацию |
| `INSUFFICIENT_SOURCES` / `FACT_CHECK_FAILED` | Проверить тему и доказательства; можно попробовать другую тему |

Приложение не повторяет платный OpenRouter POST автоматически при сетевой ошибке или HTTP-ошибке. Перезапуск runner во время работы и ручной повтор задания могут запустить исследование заново. Ограничение расходов задайте на ключе OpenRouter.
